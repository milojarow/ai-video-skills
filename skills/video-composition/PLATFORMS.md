# Platforms — Constraints by Distribution Channel

Aspect ratios, durations, safe-zones, and platform-specific quirks for the channels where these shorts are published. Pre-publication checklist for each.

The validated production campaigns primarily target **WhatsApp Stories** — that's the validated platform. IG Reels and FB Stories are documented from public specs; not validated end-to-end in this project yet.

---

## WhatsApp Stories

The primary target for this project. Full validation: pilot + short-02 published successfully.

### Specs

| Property | Value |
|---|---|
| **Aspect ratio** | 9:16 (vertical) |
| **Recommended resolution** | 1080×1920 |
| **Min resolution** | 720×1280 (degraded, not recommended) |
| **Max duration per Status segment** | 30 seconds |
| **Max duration via concatenation** | Up to 30s × multiple statuses if needed |
| **Audio default** | Plays with sound on tap; muted by default in some configs |
| **Captions** | Burned-in only (WhatsApp doesn't auto-generate) |
| **File format** | MP4 (H.264 video, AAC audio) |
| **Recommended bitrate** | 4-8 Mbps for 1080p |

### Safe-zones (UI overlays)

WhatsApp's native UI elements occupy parts of the canvas. Captions and key visual content must avoid these zones.

```
+-----------------------------------+
|  [Avatar][Username]    [✕]        |  ← Top: ~ 200px (status bar + sender)
|                                   |
|                                   |
|                                   |
|     SAFE CONTENT ZONE              |
|     (this is where your visuals    |
|      and captions live)            |
|                                   |
|                                   |
|                                   |
|                                   |
|  [➤] Reply / Forward / etc.       |  ← Bottom: ~ 290px (15% of 1920)
+-----------------------------------+
```

**Caption placement guideline:** anchor at `bottom: 380px` from the canvas bottom (i.e., y = 1540 from top in a 1080×1920 canvas). This puts captions at ~80% of canvas height — below the action zone, above the WhatsApp UI strip.

In the build script, this is the constant:

```javascript
const CAPTION_BOTTOM = 380;   // px from bottom; ~y=1540 from top
```

Tested in pilot and short-02 — captions never collided with WhatsApp UI.

### Watermark placement

Watermark in any of the 4 corners works. The corner rotation pattern (see [WATERMARK.md](WATERMARK.md)) keeps it visible without parking on top of WhatsApp UI for too long. Specifically:
- Top-right: clear (no UI competes)
- Bottom-right: **WhatsApp's reply icon may overlap** at the very bottom — so dwell here is acceptable but the watermark should sit at `bottom: 40px` or higher
- Bottom-left: similar caveat
- Top-left: clear

Validated `WM_INSET = 40` keeps the watermark ~40px from the canvas edge. Even at the bottom corners, it sits above the WhatsApp UI strip.

### CTA timing

The URL typewriter (see [ENDINGS.md](ENDINGS.md)) should:
- Be fully visible for ≥1 second before any fade-out begins
- Stay readable on phone screens — font size 60-72px works at 1080×1920

For WhatsApp specifically: the URL doesn't auto-link in Status. Users either need to memorize it, take a screenshot, or DM the contact. Make the URL **memorable and short** if possible (`acme.mx/plan` instead of `acmeseguros.com/...`).

## Instagram Reels

Documented from public specs; **not yet validated** in this project.

### Specs

| Property | Value |
|---|---|
| **Aspect ratio** | 9:16 (vertical) |
| **Recommended resolution** | 1080×1920 |
| **Max duration** | 90 seconds (per Reel) |
| **Audio** | Plays with sound by default (unlike WhatsApp) |
| **Captions** | Auto-generated by Instagram, but quality varies — burning your own is recommended |
| **Cover image** | 1080×1920 still — generated automatically from frame 1 unless overridden |

### Safe-zones

IG Reels has its own UI overlays — different from WhatsApp.

```
+-----------------------------------+
|                                   |  ← Top safe (no overlay)
|                                   |
|                                   |
|                                   |
|     SAFE CONTENT ZONE              |
|                                   |
|                                   |
|                                   |
|                                   |
|  [Username] [Caption]              |  ← Lower left: text overlay (~250px from bottom)
|  [♥][💬][↗][⋮]                       |  ← Right edge: action icons (~250px wide)
|  [⏵ Audio Track]                   |  ← Bottom strip: audio attribution
+-----------------------------------+
```

**Caption placement guideline:** anchor at `bottom: 280-320px` (a bit higher than WhatsApp because the lower-left has the username/caption overlay). Watermark in top corners or bottom-right is safe.

### IG-specific considerations

- **Audio attribution**: if you use external music in the rendered video (your `music.mp3` from ElevenLabs), Instagram won't show audio attribution because it's not their licensed library. That's fine for our use case (the music is part of the rendered video).
- **Cover image**: by default IG uses the first frame. If your fade-in is from black, IG will pick a black thumbnail. Use a custom cover (a single-frame brand card) when uploading.

## Render output settings (cross-platform)

For HyperFrames, `--quality high` produces:
- **CRF 15** (visually lossless at 1080p)
- **x264 slow preset** (or NVENC if `--gpu`)
- **MP4** container
- **AAC** audio at 44.1kHz, 192 kbps

This is **above** the recommended platform bitrates — so when WhatsApp / IG / FB re-encode the video for distribution, the source quality is high enough that the re-encoding doesn't visibly degrade.

If you're delivering to a client (not directly publishing), `--quality high` is the right call.

If you're testing or iterating, `--quality draft` (CRF 28, ultrafast) is fine — outputs are obviously lower quality but render fast.

---

## Cross-platform best practices

1. **Always render at 1080×1920** — every target platform recommends this; downscaling later is invisible.
2. **Burn captions in** — don't rely on platform auto-captioning. Quality varies by platform and language.
3. **Loudness target: -16 LUFS** — recommended for IG/WhatsApp (different from broadcast TV's -23 LUFS). Verify with `ffmpeg -i video.mp4 -af loudnorm=I=-16:print_format=summary -f null -`.
4. **Test on actual phone before publishing** — the desktop preview never quite matches what users see. Send a test to your own phone via WhatsApp / IG DM.
5. **Adopt platform-aware safe-zones**: the build script's `CAPTION_BOTTOM` constant should change per platform if delivering the same content to multiple channels.
